# 出发点

- 分文件夹整理工作繁琐
- 一个笔记可以跨多个领域，不便分类
- 堆在资料库中，想回顾只能找到指定目录查看，容易吃灰
- 不想每次写笔记都写一大堆格式和属性

# 思路

- 不通过文件夹，而是通过分类将笔记联系起来
- 笔记中尽可能使用链接的方式
	- 在编写和浏览笔记的过程中点击链接即可跳转
	- 产生更多的灵感
	- 帮助回顾
- 如果需要类似目录一样的东西，可以通过分类+数据库的方式写成大纲
- 通过在一个空笔记中插入多个可组合的模板实现快速写作

# 位置与文件夹

- 所有笔记都放在**库根目录**，不按主题建文件夹。
- 库根下只留五个功能目录：
	- `分类/` —— 每个分类一个同名入口页（如 `分类/个人思考.md`），页内列出本类笔记。分类之间的关系靠链接，不靠目录树。
	- `分类/数据库/` —— 每个分类一张同名的 `.base` 表格视图，按分类属性筛出本类笔记。
	- `附件/` —— 笔记中的附件，比如笔记里引用的图片。
	- `模板/` —— 模板文件（核心「模板」插件的模板文件夹已指向这里）。
	- `资料/` —— 未处理的源文件，不是正式笔记：网上下载的视频、PDF、docx、书籍等，Obsidian 浏览器扩展（Web Clipper）抓取的剪藏，别人的笔记。处理提炼后的成果放回库根目录成为正式笔记。

# 属性三件套（frontmatter）

每篇笔记只要求三个属性：

```yaml
---
创建时间: 2026-10-12
分类: "[[编程基础|编程基础]]"
标签:
  - "[[Python]]"
  - "[[编程基础]]"
---
```

- `创建时间`：ISO 日期 `YYYY-MM-DD`，写创建那天，之后不改。
- `分类`：**值必须是指向 `分类/` 下同名入口页的链接**，写成 `"分类名"`。它既不是纯文本，也不放多个分类。
- `标签`：列表，2–4 个，用来横向串起跨分类的话题。

别人写的属性（格式、顺序、额外字段）一律保留、不改写；只补缺失的那一项。

# 分类的三件套：属性链接 → 入口页 → 数据库视图

一个分类要真的能用，三样东西得同时在场：

1. 笔记的 `分类` 属性指向入口页；
2. `分类/分类名.md` 入口页存在，并列出本类笔记；
3. `分类/数据库/分类名.base` 以 `分类 == link("分类/分类名", "分类名")` 为筛选条件。

缺任何一件，分类就退化成一个标签：入口页是空的，或者视图永远查不到东西。

# 链接优先

- 正文里能写 `wikilink` 的地方，就不要写“某个笔记里讲过”。
- 每篇笔记 3–6 个内部链接。因已有笔记 X 而新写一篇时，同时把新笔记加进 X 的相关笔记。
- 每篇结尾固定一节 `## 相关笔记`，每条链接后跟一行说明和关系标注。

```markdown
## 相关笔记

- [[语言的边界]] —— **Context**：语言与认知边界那条线的另一条分支。
```

关系标注用这几个词：Extends / Contradicts / Confirms / Prerequisite / Applies / Example-of / Context。

# 模板

- 模板都放 `模板/`，目前是 `模板/笔记模板.md`：带三件套属性、骨架小标题和“相关笔记”结尾（`分类` 默认填 `个人思考`，按实际分类改）。
- 用 Obsidian 核心「模板」插件插入（模板文件夹已设为 `模板`）；库内没有 Templater，也不装。
- 语法：`{{title}}` 取文件名，`{{date:YYYY-MM-DD}}` 取当天日期。

# 日常记笔记的分工

- 用户把原始素材（想法、对话、资料）交给 Chief of Staff，由 Chief 转给 VaultKeeper。日常记笔记是 VaultKeeper 的常设职责。
- VaultKeeper 负责起草与维护：先搜索标题/别名/标签查重，近似则扩写那篇、不另起对手篇；再按本文规范写属性、连链接、结尾留相关笔记。
- 用户只提供内容，不负责格式。
- 周检固定**每周日 20:00**，只报告不静默修改：孤儿笔记、缺属性、断链、重复观点、过长到像目录的笔记。
