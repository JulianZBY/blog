# 仓库笔记规范

本篇是整个仓库的最高规范。复盘官 每次运行前必须先读这篇；人写笔记也按这个来。规范本身是活的：修订直接改本文，并在文末「变更记录」留痕。

## 文件夹：只有五个，各司其职

```
Vault/
├── *.md            全部笔记，平铺根目录
├── 分类/           属性笔记 + 属性值笔记（索引层）
│   └── 数据库/     唯一子文件夹，只放 .base 文件
├── 附件/           图片、导图等插入物，分类整理
├── 资料/           原始素材（小说、帖子、爬取结果），几乎不加工
└── 模板/           我自用，智能体不碰
```

## 属性规则

- 每篇笔记必须有 frontmatter；最低要求 `创建时间`（`YYYY-MM-DD`，填创建那天，之后不改）+ `分类`
- 属性值如果是概念，写成 wikilink 指向 `分类/` 下的同名值笔记：`分类: "问题排查"`
- 属性分单值/多值：
  - **单值属性**（如 `日期`）：只有属性名在 `分类/` 有笔记，属性值不建笔记
  - **多值属性**（如 `人物`、`分类`、`来源`、`标签`）：属性名在 `分类/` 有笔记，**每一个值**也在 `分类/` 有同名笔记
- 新建笔记前先看 `分类/` 已有的属性词汇，能复用不新造；确实没有再新建属性（属性笔记 + 各值笔记 + base 一次配齐）
- frontmatter 必须以 `---` 开始并以 `---` 闭合：不闭合的属性 Obsidian 不解析，等于没写（属性面板为空，base 与搜索都收不到）

## 属性笔记与值笔记的标记（机器可读的身份）

| 身份 | frontmatter 标记 | 例子 |
|---|---|---|
| 属性笔记（属性名对应） | `标签: 属性` | `分类/人物.md`、`分类/属性.md` |
| 值笔记（多值属性的值对应） | `属性: <所属属性>` | `分类/问题排查.md` → `属性: 分类` |

`标签.md` 和 `属性.md` 本身也是属性笔记，同样标 `标签: 属性`；`属性.md` 同时是「标签」属性的一个值——体系自洽。

## 分类/ 下的笔记 = 索引

- 每篇分类笔记正文里内嵌一个 base：`<!-- 附件图片 同名.base 未随发布迁移，请手动处理 -->`，base 文件放 `分类/数据库/`
- **属性笔记**的 base：列出所有含该属性的笔记（`属性.md` 特殊：它是属性总表，列出所有 `标签` 含 `属性` 的笔记）
- **值笔记**的 base：列出所有该属性取该值的笔记
- 每篇分类笔记开头用一两句话说明这个属性/值是干什么用的

## 链接与相关笔记

- 正文里凡与别的笔记有实际关联的概念，就地挂 `wikilink`；不为链而链
- 文末设「相关笔记」区，每条链接带一句作用说明（说明它和本篇是什么关系：Context / Confirms / 同类 等）

## 附件与资料

- 笔记里插入的图片、导图放 `附件/`，按用途分子文件夹；引用用 `<!-- 附件图片 文件名 未随发布迁移，请手动处理 -->`
- 原始资料放 `资料/`，不做加工、不加属性规则

## 复盘官的工作约定

- 数据源：当天 Multica 会话（issue/评论/运行记录）+ 本机 pi 会话日志（`~/.pi/agent/memory/daily/`）
- 产出：根目录当日复盘笔记（`YYYY-MM-DD 复盘.md`，`分类: "复盘"`）、问题笔记（一个问题一篇：现象/根因/为什么会发生/立了什么规矩）
- 发现需要立规矩时：**直接修订**对应规范类笔记，并在其文末「变更记录」追加一行（日期 + 改了什么 + 因为哪个问题）
- 新建笔记一律遵守本规范；新属性一次配齐（属性/值笔记 + base）
- 批量审计笔记属性时，用解析器验证 frontmatter 合法性，不做文本匹配——文本匹配验证不了结构错误（2026-10-27 曾有 42 篇未闭合漏检）
- 建完属性词汇后做闭环验证：确认新 base 视图真能取到笔记，词汇升级与存量迁移是两步工作
- 不碰：`模板/`、`资料/`、`附件/` 里既有文件、不相关笔记的正文
