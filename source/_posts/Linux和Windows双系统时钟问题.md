# 背景

这台机器装着 Linux 和 Windows 双系统，Hermes 运行在其中的 Linux 上。两边对硬件时钟的存法不一样，一个按 UTC 记，一个按本地时间记，切换回来之后系统时间比真实时间快了约 7 小时 55 分。

# 分析

先用四个独立的 NTP 源交叉核对。四个源给的时间一致，机器时间确实快 7 小时 55 分，排除了单个时间源出错的可能。

再看 chrony。它默认只做 slew，也就是把时钟调快或调慢，慢慢追；不做 step，也就是不直接跳变。偏差只有几秒时 slew 够用，差到几个小时，追平要花极长时间，所以时间一直停在快的位置。

# 解决方案

手动跳一次，`sudo chronyc makestep`。到写这篇时这一步的执行状态还没确认。

防复发，在 chrony 的配置里写 `makestep 1.0 -1`，让它在启动后允许一次性跳变，偏差大时不必靠 slew 慢慢追。
